# Единая ссылка для пользователей А19

## Что готово

Серверная функция `api/github.js` обращается к приватному `iamkurakov/a19_data` через токен, находящийся **только в переменной окружения сервера** `A19_GITHUB_TOKEN`. Браузеры заказчицы, её коллег и всех пользователей ссылки токен не хранят и не вводят. Публичный сайт продолжает работать по адресу `https://iamkurakov.github.io/a19/`.

Сервер разрешает операции исключительно с заказами, подтверждёнными ставками и чтение приватной модели. Он никогда не запрашивает и не записывает `ideal_potolok` или `ideal_potolok_data`. Внешние изменения одного заказа через GitHub SHA не затираются молча.

## Что требуется для запуска

**Публикация кода в GitHub Pages сама по себе не запускает серверный API.** Нужен серверный хостинг (например, Vercel). Для этого в репозитории есть `api/github.js`, `api/health.js`, `vercel.json`.

1. Подключить проект `iamkurakov/a19` к Vercel. Для Node serverless route не требуется устанавливать зависимости; используется встроенный `fetch`.
2. В настройках **сервера**, а не GitHub Pages, указать переменную `A19_GITHUB_TOKEN` со значением **уже существующего** ограниченного токена `a19_data` (в чат токен не передавать).
3. После публикации проверить `https://<выданный-домен>/api/health`: должно быть `ready: true`.
4. В открытом репозитории поменять только `config/shared.json`: `"api": "https://<выданный-домен>"`; GitHub Pages автоматически подхватит конфигурацию при следующем открытии сайта. Это публичный адрес API, не секрет.
5. Проверить без токена на другом компьютере: загрузку модели, создание заказа и появление `orders/<id>.json` в приватном репозитории.

Если сервер не опубликован, `config/shared.json` остаётся с `api:null`, старый режим владельца продолжает работать, а автоматического общего доступа **нет**.

## Доступ по ссылке

По требованию заказчика входа в интерфейс нет. Если сервер не требует дополнительного ключа, доступ к данным получит любой, кто открывает публичный адрес А19, включая посторонних. CORS не заменяет авторизацию. Это свойство общего доступа, а не ограничение GitHub Pages. Сервис не следует включать в публичный режим для конфиденциальных заказов без согласия владельца.

Если нужно ограничить доступ без регистрации и ввода кодов, можно задать серверу `A19_SHARED_KEY` и раздать единую ссылку вида `https://iamkurakov.github.io/a19/#a19=<общий-длинный-ключ>`. Пользователи только открывают ссылку, ничего не настраивая. Сам ключ не должен находиться в публичном коде или `config/shared.json`. Ссылка с ключом не должна попадать в публичную документацию.

## Сохранение и ограничения

Браузер сохраняет локальную резервную копию. Система подтягивает другие заказы при запуске, возвращении во вкладку и раз в минуту. Конфликт правок одного заказа не перезаписывается молча. Github Contents API подходит для ограниченного тестирования, но не заменяет полноценную транзакционную БД при большом количестве одновременных менеджеров.
